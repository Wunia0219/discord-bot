# 玩家戲籌與整群重設

使用 `/戲籌管理` 私人面板中的「玩家戲籌」與「重設全群」，沿用管理員／指定戲籌管理身分組檢查。對象為目前伺服器所有已建立錢包的玩家，包括只有簽到及餘額為零的玩家；不另外建立管理員或未參與成員的錢包。完整操作見 [指令說明](discord-commands.md)。

## 指令

- 「玩家戲籌」：每頁 20 位，顯示目前餘額與累積局數，使用下一頁／回到第一頁按鈕。查詢不改變資料，Firestore 使用文件 ID 的伺服器前綴範圍及原有單欄索引，直接讀錢包，不掃描遊玩歷史或 Discord 全體成員。
- 「重設全群」→「確認重設全群」：原子重設本群全部現有錢包為 10,000，完成後立刻列出每人的實際重設前餘額及重設餘額。保留週簽到、全部回合、摘要、里程碑及開轉冷卻。未確認不執行。
- 「上次重設報表」直接開啟最近一次結果，使用前後翻頁，不輸入編號，不提供歷史整群報表查閱。翻頁時若已完成另一筆重設，提示重新開啟，不混用兩次資料。讀取報表不再重設；同一確認卡重複點擊也只回傳原結果，即使 Discord 產生不同的新 interaction ID。重新開啟並確認另一張確認卡，才會執行新一筆重設。

玩家戲籌是查詢當下的資訊。重設不採用先前查詢結果，而是在同一筆交易內重新讀取全部權威錢包、寫入 10,000 與保存原餘額。開轉、簽到、發放與新錢包建立共用既有 metadata，與重設交易序列化；SQLite 使用 BEGIN IMMEDIATE。重設前已結算的回合納入原餘額，重設後結算的回合從新餘額開始。尚未完成的動畫可能仍顯示上一局，其已提交結算不會再入帳；原請求重送只回傳舊回合及最新錢包。

## 保存、成本與容量

每次重設只新增一份 `operations` 精簡憑證 `reset:<interaction ID>`，含操作者、時點、總額、人數與連續帳本編號範圍；每位玩家新增一筆 `ledger.kind=reset`，包含已是 10,000 的玩家。**不再於憑證內重複保存每人 before/after 陣列，也不另建完整報表文件或集合。** 顯示時直接讀取該範圍的既有帳本，每頁最多 20 人。帳本內保留 delta 供連續性驗帳，玩家與管理員介面不把重設顯示為一般加減款，而是「餘額重設／重設後餘額 10,000」。必要帳本及去重憑證仍隨重設累積，不能宣稱資料庫完全不成長；不刪除原簽到或遊玩歷史。

新憑證為 reset version 2：`{reset:統計, range:{first,last}}`，大小為數百位元組，不隨玩家數量線性增加。Firestore 同次寫入增加一個純量 `resetKey=<guild>_<補零的首筆帳本編號>`，以現有自動單欄索引找到最近一筆，不需新增複合索引。上次報表每頁通常為 1 份憑證＋最多 20 份帳本讀取，零寫入；未查閱時沒有額外讀寫或輪詢。舊 version 1 完整憑證保留相容；缺少新索引時只查重設帳本的原操作連結，不查普通遊玩帳本、不批量改寫歷史。從備份匯入時兩種格式均建立同一最新索引。

Firestore v2 的重設交易讀取 metadata、去重結果及 N 份錢包，寫入 `2N+2` 份文件（N 錢包、N 帳本、metadata、單份結果）；v1 沿用四份查帳副本，為 `6N+2`。供應商及交易重試另計；現行持久額度仍保守預留重試成本。重送原指令為零寫入。錢包同份文件增加一個最近重設標記，不新增正常開轉、簽到或狀態查詢的雲端讀寫次數，不增加輪詢或排程。

本版以「全部成功或全部不變」為優先，SQLite／Firestore v2 單群單次上限 **100 份錢包**，v1 **60 份**；Firestore 另在寫入前以估算 6 MiB 限制交易資料量。超出時整筆拒絕，不分段重設、不略過玩家。這不是可無限擴充的設計；正式營運規模超出前，須設計受控維護／分批結算機制，不能直接提高常數後宣稱仍有相同保證。

SQLite schema 遷移至 3，只增加最近重設的部分索引，七份備份資料表不變。本功能於 0.2.8 加入，目前產品版本為 0.3.0。畫面保留最近一次重設標記，完整多次重設及回合仍在帳本；最近 100 局是畫面快取，並非完整保存上限。歷史較長時先顯示明確的最近重設摘要，載入相應舊回合後移到正確時間位置；以前一局 ID 定位，避免毫秒相同時排錯。

## 備份與驗證

SQLite、完整與增量 Firestore 備份、Worker 分段快照及 v1／v2 匯入都保留精簡原憑證，並相容舊完整結果。只有該批第一筆帳本連結原操作，其餘明確為 null，跨 20 筆 checkpoint 不重複保存憑證；驗帳逐筆比對範圍、群組、玩家、操作者、時間、金額、總額、人數與連續性。還原從原帳本與操作重建最近重設標記，重送舊重設不會覆蓋還原後的新遊玩。新憑證出現後，不能直接回退至不理解 version 2 範圍格式的舊 Worker。

新增驗證涵蓋本群隔離、零餘額與簽到玩家、重送去重、權限、原子失敗回滾、跨服務併發、簽到與歷史保留、REST／SDK 相容及跨分段備份還原。正常／快停參數及產品版本均不調整。2026-10-27 已部署至現有 Discord 測試服務，入口為 `/戲籌管理` 私人面板；部署驗收沒有對雲端玩家執行發放或重設。
