# Discord 指令與管理面板

玩家與管理員各保留一個入口，目前產品版本為 0.3.1。

| 使用者 | 入口 | 操作 |
|---|---|---|
| 玩家 | `/戲籌` | 查看自己的餘額與週簽到提示，按「開啟遊戲」直接進入 |
| 管理員／指定身分組 | `/戲籌管理` | 開啟只有自己看得到的管理面板 |

`/簽到` 已從註冊定義移除。Discord 快取中的舊指令只回覆遊戲入口，不查錢包或發放獎勵。週簽到只能在遊戲內的「週簽到」視窗領取，獎勵仍為 500／500／1,000／1,000／1,000／2,000／4,000。

## 管理操作

- **玩家戲籌**：本群所有已有錢包的玩家，包含只有簽到的玩家；每頁 20 位。使用「下一頁／回到第一頁」，沿用文件 ID 升冪索引與游標，沒有 offset 掃描，也不新增索引。
- **發放戲籌**：表單搜尋本群玩家、輸入數量與原因，沿用原本單筆與每日上限。結果卡可直接查玩家紀錄、收回這筆誤發或繼續發放。
- **查詢紀錄**：選一位玩家後，使用分類與期間選單，以及「更早的紀錄／回到最新」。發放紀錄選單可以直接選擇誤發來收回；看到重設紀錄時，可按「上次重設報表」查看最近一次結果。
- **重設全群**：先顯示獨立確認卡，按「確認重設全群」才執行。將本群所有現有錢包設為 10,000，保存確認當下每人的實際餘額；週簽到及遊玩歷史保留。「上次重設報表」直接開啟最近一次結果，不需要編號；僅提供最新報表。翻頁期間又完成新重設時，舊頁連結會提示重新開啟，避免混頁。交易與容量見下方。

所有回覆均為私人卡片，不發群組公告、不推播提及。每個按鈕、選單與表單提交都重新檢查伺服器、頻道、開啟者及管理權限；失去角色後，舊面板也不能操作。Discord 原生的應用程式頻道權限保留；後端另使用 `DISCORD_COMMAND_CHANNEL_IDS` 驗證，包括管理員與遊戲啟動，避免管理員繞過原生權限後在其他頻道操作。

## 成本與重複提交

開啟面板、表單與確認卡不讀寫 Firestore；不保存 UI session，不新增集合或輪詢。名單只讀本頁最多 21 份錢包（第 21 份判斷是否有下一頁），歷史沿用原分頁查帳。

上次重設報表由既有帳本按需組成，不另外累積整群的餘額明細副本。每次重設仍保留小型不可變憑證及每人一筆必要帳本，支援查帳與舊請求去重；新憑證只存統計及連續帳本編號範圍。查閱每頁通常讀取 1 份憑證與最多 20 份帳本、零寫入；沒有定時更新報表。升級前尚未有 `resetKey` 索引的舊報表，沿用重設帳本連結唯讀查找，不掃描普通遊玩歷史，也不另跑資料遷移。

金融操作以「開啟該張表單／確認卡的 Discord interaction ID」作為原請求鍵。即使重複點擊產生新的 interaction ID，也只回傳原結果，不再次發放、收回或重設。表單與確認卡有效時間 30 分鐘；報表查閱不受此期限限制。重新開啟新的確認卡並確認，才是新一筆重設。

雲端查詢及提交先私密 ACK，再更新原回覆；按鈕開表單及啟動遊戲立即回應。這避免等待資料庫超過 Discord 回應期限，也避免每次翻頁新增訊息。

## 註冊及測試

`npm run commands:register` 以 PATCH 更新既有指令，保留兩個指令 ID 與原權限，只刪除本應用程式的群組／全域 `/簽到`。不覆寫其他指令，也不刪除 Activity Launch。舊用戶端送出的管理子指令仍有後端權限保護，但新版選單不再列出它們。

`tests/discord-panel.test.js` 覆蓋表單、零寫入面板、游標翻頁、原金額報表、重複點擊、過期與跨人／跨群／跨頻道拒絕、撤銷權限及簽章 HTTP 回應。`tests/discord-registration.test.js` 核對更新範圍、保留 ID／Launch 與已移除指令的遠端診斷。

## 保存、成本與容量

每次重設只新增一份 `operations` 精簡憑證 `reset:<interaction ID>`，含操作者、時點、總額、人數與連續帳本編號範圍；每位玩家新增一筆 `ledger.kind=reset`，包含已是 10,000 的玩家。**不再於憑證內重複保存每人 before/after 陣列，也不另建完整報表文件或集合。** 顯示時直接讀取該範圍的既有帳本，每頁最多 20 人。帳本內保留 delta 供連續性驗帳，玩家與管理員介面不把重設顯示為一般加減款，而是「餘額重設／重設後餘額 10,000」。必要帳本及去重憑證仍隨重設累積，不能宣稱資料庫完全不成長；不刪除原簽到或遊玩歷史。

新憑證為 reset version 2：`{reset:統計, range:{first,last}}`，大小為數百位元組，不隨玩家數量線性增加。Firestore 同次寫入增加一個純量 `resetKey=<guild>_<補零的首筆帳本編號>`，以現有自動單欄索引找到最近一筆，不需新增複合索引。上次報表每頁通常為 1 份憑證＋最多 20 份帳本讀取，零寫入；未查閱時沒有額外讀寫或輪詢。舊 version 1 完整憑證保留相容；缺少新索引時只查重設帳本的原操作連結，不查普通遊玩帳本、不批量改寫歷史。從備份匯入時兩種格式均建立同一最新索引。

Firestore v2 的重設交易讀取 metadata、去重結果及 N 份錢包，寫入 `2N+2` 份文件（N 錢包、N 帳本、metadata、單份結果）；v1 沿用四份查帳副本，為 `6N+2`。供應商及交易重試另計；現行持久額度仍保守預留重試成本。重送原指令為零寫入。錢包同份文件增加一個最近重設標記，不新增正常開轉、簽到或狀態查詢的雲端讀寫次數，不增加輪詢或排程。

本版以「全部成功或全部不變」為優先，SQLite／Firestore v2 單群單次上限 **100 份錢包**，v1 **60 份**；Firestore 另在寫入前以估算 6 MiB 限制交易資料量。超出時整筆拒絕，不分段重設、不略過玩家。這不是可無限擴充的設計；正式營運規模超出前，須設計受控維護／分批結算機制，不能直接提高常數後宣稱仍有相同保證。

SQLite schema 遷移至 3，只增加最近重設的部分索引，七份備份資料表不變。畫面保留最近一次重設標記，完整多次重設及回合仍在帳本；最近 100 局是畫面快取，並非完整保存上限。歷史較長時先顯示明確的最近重設摘要，載入相應舊回合後移到正確時間位置；以前一局 ID 定位，避免毫秒相同時排錯。


備份、還原及匯入均支援 reset version 1／2，逐筆核對帳本範圍、群、玩家、金額及總額；原請求重播不覆蓋新遊玩。格式相容要求見[恢復](recovery.md)。
