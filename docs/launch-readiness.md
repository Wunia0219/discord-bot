## 多人結算

雲端唯一 writer 將會修改共用編號的交易排入上限 32 筆、最多等待 10 秒的佇列；開始交易後不以等待逾時取消它。未開始且過期的工作不觸及資料庫，回傳明確的忙碌狀態，前端保留原請求編號。讀取、登入、動畫與備份不排在該佇列。跨 writer 的明確 ABORTED 仍最多三次並加入退避；不自動重試回應不明的提交。

錢包背景刷新由固定 15 秒改為每次 15–20 秒，減少同時開啟後的同步讀取。這不是消除所有等待，也不是單靠 Blaze 提高速度。全域帳本編號、歷史索引與每局原結果保持相容，不以移除記帳保障換取速度。

隔離測試：2／5／8／10 人每 60ms 錯開送出，以及 20 人同時送出，全數結算成功；集中情境首次衝突拒絕 0、重複入帳 0。`test-results/backup-scale-report.json` 的耗時只代表模擬器，不是實際 Discord 延遲。真人操作的剩餘驗收依 [收尾計畫](roadmap.md)。

## 分塊備份與完整還原

備份 archive format 2 與 Firestore schema v2 是不同層級；本次不遷移或重設玩家 namespace。

- 歷史以約 64 KB 的不可變分塊儲存，AES-GCM 加密、SHA-256 校驗；目錄另用獨立衍生 HMAC 金鑰認證，不能任意抽換或重排分塊。
- 後續備份沿用既有歷史分塊，只追加新帳本／原請求／回合並更新錢包及公告快照。每個 checkpoint 與游標在同一 SQLite 交易提交，失敗不重複追加。
- 七表全量驗帳以分塊位置索引處理，最多快取八個解密分塊；不再每 20 筆解密、重寫及重加密完整歷史，也不把全歷史逐列寫入 SQL 暫存表來驗帳。
- 同一 Firestore readTime 貫穿備份；僅驗帳通過後發布。保留三份成功世代，共用分塊只有在沒有任何世代或候選引用時才清除。失敗候選不取代原有效副本。
- 原本 8 MiB 的完整 JSON 限制已移除，改採 128 MiB／8,192 個分塊的資源保護界線，不宣稱無限容量。維運告警需涵蓋容量；未來接近界線時應規劃下一階段，不能刪除玩家歷史或擅自提高免費用量。
- 新工具仍可解密原 format 1。新格式透過固定世代的分頁下載，避免單次 Worker 回應組合整份歷史；所有分塊及目錄到齊後才建立輸出檔案。

6,000 局、超過 11 MiB 的真實格式隔離資料已驗證七表還原一致；包含重建 workerd 後全量驗帳與分頁下載。另有舊格式、目錄／密文竄改、失敗候選、共享分塊保留及超界拒絕測試。測試證據：`segmented-backup-report.json`、`segmented-workerd-report.json`、`cloud-runtime-report.json`。

## 費用保護

保留既有全域 40,000 讀／15,000 寫、維護 6,000 讀及公告 3,000 讀等上限與全部原計數，不因 Blaze 調高。備份 REST 沒有隱藏重試，每次嘗試先預留實際請求上限，失敗不退款；1,000 局增量備份預留從 18,246 降為 3,041，沒有減少備份內容。

Cloudflare SQL 的零成本額度檢查不再寫回零值；不成長的文件不再重寫成長紀錄。每分鐘首次讀取持久額度後，記憶體彙總隨每次成功持久寫入更新，換分鐘或重建時重新計算；子額度失敗不污染全域快取。這些調整不刪除歷史、不降低已記錄使用量。

Cloudflare Workers Free 與 Firebase Blaze 分別管理。Cloudflare SQL 免費範圍亦有每日讀寫限制，不只是 Firestore；完整歷史驗帳因此不採逐列 SQL 暫存。官方限制見 [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/)。應用程式估算不是 Google 帳單硬上限，預算告警亦不會自動停止扣費；未啟用原生付費備份、PITR 或新增付費服務，詳見 [費用限制](billing-safety.md)。

## 發布與回退

發布前封存原 Worker、綁定、私密設定及加密備份於 `backups/launch-release-20261026/`。先保留已通過 workerd 驗證、支援新備份格式但沿用原結算／額度程式的相容回退版本，再發布完整優化及前端。新舊後端處理新／舊中文指令名稱，Discord 指令以原 ID 更名，保留既有權限。

程式回退沿用相同 Worker、DO、資料庫及原額度，不回灌舊快照。**format 2 發布後不可直接回退到只懂 format 1 的歷史版本。** 使用下方記錄的相容版本；必要時按 [雲端手冊](cloud-runtime.md) pause → 最新備份 → export/release → 還原驗證 → 回傳原額度，再移交唯一 writer。新版 `cloud:control export` 支援分頁下載與同一 export receipt 的重試。

目前實際 namespace 是使用者既有試玩資料所在的 `test`，本次保留其全部進度與初始戲籌規則。不可為了「正式上線」直接換空白 production namespace；若要更改新玩家初始額度，須另作明確設定及資料驗證。
