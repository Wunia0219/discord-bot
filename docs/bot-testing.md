# Bot 功能測試

## 自動測試

v2 另外由 `tests/firestore-v2.integration.js` 驗證實際讀寫量、冷登入一讀、原始資料遷移、跨裝置、完整歷史、備份及回退至 v1；`tests/firestore-schema.test.js`、`firestore-import-plan.test.js`、`wallet-sync.test.js` 驗證無損快取、dry-run 與前端同步。指標與環境界線見 [Firestore v2](firestore-v2.md)。

`tests/firestore-highlights.integration.js` 驗證公告與結算原子提交、普通局六次寫入、並行去重、派送鎖、長時間 429、逾時／重啟、跨群隔離、持久子額度及公告備份回退；只使用官方本機模擬器與假 Discord 回應。`tests/discord-readiness.test.js` 驗證啟動診斷不修改遠端或洩漏密鑰。手動使用 `npm run discord:check -- --discord` 時才會以現有應用程式權杖唯讀查詢 Discord，詳細界線見 [Discord 啟動驗收](discord-readiness.md)。

需要 Node.js 24，在專案根目錄執行：

```sh
npm ci
npm run test:bot
```

已安裝依賴時，直接執行 `npm run test:bot`。全部遊戲、前端與 bot 回歸測試使用 `npm test`。

測試會在 `127.0.0.1` 的隨機連接埠啟動 HTTP 服務，以臨時 Ed25519 金鑰簽署模擬 Discord 互動，並使用獨立的記憶體 SQLite 資料庫。測試不需要 `.env` 或 Discord Token，不呼叫 Discord、不註冊指令，也不讀寫現有帳號資料庫；結束後關閉服務與資料庫。

`tests/bot-interactions.test.js` 驗證簽署請求經 HTTP 入口到指令處理及 SQLite 的完整流程；同一指令還會執行既有指令、HTTP API、錢包與登入 session 測試。午夜案例使用可控時鐘，不需要等待真實換日。

`tests/database-audit.test.js` 在獨立臨時資料庫中注入錯誤：變更派彩或盤面、移除回合／重送紀錄、變更快取結果、跨玩家連結、不安全整數與非法 JSON 等。確認驗帳回報異常、來源內容不變，而且備份不接受異常來源；這些測試不修改現有玩家資料。`test:bot` 也會執行原有資料庫遷移、併發、WAL 備份及安全還原測試。

`tests/operations.test.js` 使用 `test-results/operations-tests/` 中的獨立 SQLite 檔案；排程使用可控時鐘，不等待真實 6 小時。實際 worker、WAL 備份及還原另外直接執行；故障僅注入測試來源，不破壞現有資料庫。自動測試不會呼叫 Firebase、建立外部監控或傳送告警。

`tests/firestore-quota.test.js` 包含持久額度、跨程序共用檔案、滾動 24 小時、傳輸／儲存門檻、文件覆寫成長及錯誤設定；列入 `npm test`。`npm run test:firestore` 另外啟動官方本機模擬器，執行 `tests/firestore.integration.js`：不同裝置同時簽到／開轉、重啟與遺失回應、管理發放／更正、完整摘要與 100 局快取、額度不足的交易回滾、非同步 HTTP／Discord、匿名存取拒絕，以及 SQLite 匯入、完整比對、中斷接續及不覆蓋既有資料。模擬器驗收不能取代 Spark 真實專案的 IAM、配額與跨裝置驗收。

`tests/pending-reels.test.js` 驗證轉輪等待網路時的首幀移動、長時間固定緩衝、符號邊界連續性，以及收到權威停點後無跳動銜接、速度連續與快停不延長。SPIN 先啟動動畫再等待錢包；尚未確認結果時快停或切到背景都不能自行落下，連線失敗會取消動畫並回復已確認盤面，同一請求重試沿用原有去重機制。減少動態偏好保留靜態等待與短動畫。0.2.5 此修正的完整回歸為 273 項通過；另在瀏覽器實際場景驗證 7 項狀態切換及 6 秒慢回應，報告位於本機 `test-results/spin-immediate-0.2.5-summary.json`。

## Discord 電腦與手機同步驗收

本輪 Spark 讀取優化另由 `tests/firestore-history.test.js` 驗證情境成本、空集合、亂序日期、跨頁不漏／不重複與查詢失敗；`tests/firestore.integration.js` 驗證實際索引查詢、台灣日期範圍、冷卻讀取及就緒合併，既有備份／還原驗收繼續執行。結果與限制見 [Spark 優化](spark-optimization.md)。採用本輪程式後，以下真人驗收仍需重新執行。

使用 `.env.server.local` 啟動 `npm run activity:server`，設定 `APP_ENV=test`、`WALLET_ENABLED=true`、明確的測試伺服器 allowlist 與資料庫；不可啟用 `LOCAL_WALLET_TEST`。僅把此服務的 4188 連接埠接到臨時通道，更新 Discord 活動根 URL 對應及互動端點。4189 的假帳號驗收服務維持本機使用。

兩台裝置都從 Discord 的同一個測試伺服器開啟活動，使用同一個帳號，並關閉自動旋轉。核對玩家 ID、初始餘額及最近紀錄；一般瀏覽器預覽和本機玩家 A 不屬於這個錢包。

1. 電腦轉一局，記下時間、下注、派彩、結算餘額；手機切回遊戲或等 15 秒，關閉後重開遊玩紀錄，應看到相同的餘額與最新一局。
2. 手機轉一局，換電腦做相同確認，驗證雙向一致。
3. 尚未簽到時由手機領取，電腦更新後應顯示今日已領取；資料庫只新增一筆簽到入帳。
4. 關閉並重新開啟兩邊活動，餘額、簽到與局數仍應一致。逐筆核對下注、派彩與結算餘額，並確認每局只有一筆 spin 帳本。

目前可見頁面每 15 秒更新錢包，切回前景也會更新；已開啟的紀錄視窗需重新開啟，才能呈現更新的清單。兩個 session 的自動測試使用模擬 Discord 身分服務，不能代替上述手機實機驗收。測試後保留裝置回報與唯讀驗帳結果，不把尚未操作的手機項目記為通過。

## 本機錢包手動驗收

服務使用 `.env.backend.local`、`LOCAL_WALLET_TEST=true`、`APP_ENV=test`、`HOST=127.0.0.1` 及明確的獨立資料檔。啟動 `npm run backend:start` 後，開啟 http://127.0.0.1:4189/wallet-test 。頁面提供測試入口、目前錢包狀態、12 項步驟、預期結果及可匯出的驗收紀錄。未親自操作的項目保持「未測試」；自動測試通過不會自動將手動項目標成通過。

四個帳號初始狀態為：玩家 A 10,000、玩家 B 10,000、低餘額 50、零餘額 0；皆未簽到且無遊玩紀錄。先做 A 首次進入與簽到，再測下注／紀錄／重新整理，之後用 B 驗證隔離。低餘額與零餘額帳號留到 W07／W08 才操作；需要新的初始條件時，先備份，改用全新的資料檔，不刪除或改寫舊帳本。初始情境只記帳一次，後續重啟不會重設籌碼。

W01–W10 可自行完成，包含單局餘額公式、跨分頁同步、餘額不足拒絕、零餘額簽到恢復、快停與自動旋轉停止。W11 的中斷／恢復與 W12 的後端重啟／驗帳由 Codex 協助，先保存當前餘額、最近紀錄及匯出筆記。後端回應不明時，應恢復同一筆請求的結算，不可當作全新下注；自動測試另行驗證重送去重。

驗收紀錄僅存於目前瀏覽器，以資料庫識別碼區分不同輪次；不是後端玩家資料。清除網站資料會失去未匯出的筆記，測試後下載 JSON 留存。問題請記錄測試編號、帳號、操作、預期／實際結果、時間及截圖檔名。錢包狀態每 15 秒或回到測試頁時更新，也可手動更新。

這一輪不包含真實 Discord OAuth／群組權限、手機實機、Webhook 推播或百人同時使用瀏覽器的負載驗收。午夜、跨群隔離、冪等與資料一致性由現有自動測試覆蓋；五個資料庫連線／100 位玩家的一致性測試不可宣稱為百人實際連線驗收。依序完成本機驗收後，再安排 Discord 測試伺服器及部署。

## Discord 手動驗收

自動測試驗證後端行為。Discord 實際顯示、指令安裝及權限設定，依 [部署說明](deployment.md) 在測試伺服器驗收；使用 `APP_ENV=test` 與獨立測試資料庫。

準備一位一般成員、一位管理員；驗證指定角色時，再使用一位具有 `CHIP_ADMIN_ROLE_IDS` 設定角色的成員，並在 Discord 指令權限中開放該角色使用管理指令。

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | 一般成員執行 `/籌碼` | 新測試錢包為 10,000，回覆標示測試環境，僅自己可見 |
| 2 | 執行 `/簽到`，接著再執行一次 | 首次增加 500；再次提示今日已領取，餘額不變 |
| 3 | 管理員對該成員執行 `/籌碼管理 發放`，數量 1,000，原因「bot 功能測試」 | 顯示紀錄編號及發放前後餘額；成員查詢增加 1,000 |
| 4 | 管理員執行 `/籌碼管理 紀錄`，選擇該成員 | 預設出現發放紀錄、原因與操作者；記下該次發放的編號 |
| 5 | 用該編號執行 `/籌碼管理 更正`，原因「測試結束」 | 收回剛才 1,000；再次更正同一筆時拒絕，餘額不再減少 |
| 6 | 再查紀錄；分類切換「簽到」與「遊戲摘要」 | 原發放標記已更正，另有更正紀錄；分類顯示對應統計 |
| 7 | 一般成員嘗試管理指令 | Discord 隱藏／拒絕指令，或 bot 回覆無權限；餘額不變 |
| 8 | 指定籌碼管理角色成員重做發放、紀錄與更正 | 可完成相同管理操作，且保留操作者紀錄 |
| 9 | 遊戲進行一局，再查 `/籌碼` 及遊戲明細 | bot 餘額與遊戲錢包一致；紀錄對應下注、派彩及淨增減 |

步驟 3～5 期間先不要花用測試發放的籌碼，以便驗證全額更正。台灣午夜與同時重送案例由自動測試涵蓋。

公告需依部署說明設定專用頻道 Webhook。先確認從 App Launcher 開啟及關閉遊戲時不再新增預設邀請卡，再在測試群自然遊玩驗收 SUPER／MEGA 的卡片、中文暱稱、倍率及合併更新。不要為了測推播變更輪帶、派彩或正式群結算；單元測試已使用獨立記憶體資料庫及既有可重播回合驗證邊界與多人成批案例。瀏覽器中的樣式預覽只是版面示意，不能代替 Discord 實際顯示與 Webhook 權限驗收。
