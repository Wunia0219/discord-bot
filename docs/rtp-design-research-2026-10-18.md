# RTP、輪帶與大獎頻率研究

研究日期：2026-10-18。對象：本專案 `kemet-20-v1`、5×3 盤面、20 條固定線。這份研究不修改正在運行的賠率、輪帶或玩家餘額。

**結論：維持現有 96% 長期 RTP 的目標，重新分配回報來源，提高低分圖標的占比及小中獎的回報貢獻；同時降低對 WILD 補線與高分圖標的依賴。不能只把低分圖標塞進輪帶。**

## 使用者這次的體驗

使用者回報：不到約 30 局、每局下注 500，兩次派彩約 11,000 與 16,000，分別約 22× 與 32× 總下注。現行程式在派彩 ≥20× 時統一播放 BIG WIN；沒有另一套獨立抽取的「超級大獎」獎池。

完整枚舉得到 P(派彩 ≥20×)=23,922/4,000,000=0.59805%，平均等待 167.21 局。平均等待不是保證間隔。

在預先固定的 n 局、獨立同分布條件下，至少兩次這類結果的機率為：

`P(N≥2)=1−(1−p)^n−n×p×(1−p)^(n−1)`

| 局數 | 至少兩次 ≥20× 派彩 |
|---:|---:|
| 20 | 0.6326% |
| 30 | 1.3922% |
| 50 | 3.6251% |
| 100 | 12.0861% |

因此，若實際少於 30 局，對應機率比 1.3922% 更低。這是「至少兩次跨過 20× 門檻」的機率，不是恰好中 11,000 和 16,000 的機率，也不是 RNG 出錯的後驗機率。回報局數是約數，尚未逐筆核對該次歷史回合。

## RTP 是如何設計出來的

令 B 為付費回合總下注，W 為該回合總派彩（若有免費轉或連消，含其後續派彩），則固定下注下：

`理論 RTP = E[W]/B = Σ P(結果 i) × 派彩(i)/B`

`實際 RTP = Σ 已結算派彩 / Σ 已結算下注`

後者不應把簽到、管理員發放、測試初始籌碼當成遊戲派彩。不同下注額的回合應以總額計算，不能把每局倍率直接取平均後冒充加權實際 RTP。英國 Gambling Commission 也區分理論與實際 RTP，並要求解讀實際數字時考慮樣本量及波動。[RTP 計算](https://www.gamblingcommission.gov.uk/licensees-and-businesses/guide/page/how-to-calculate-return-to-player-rtp)、[樣本量與波動](https://www.gamblingcommission.gov.uk/licensees-and-businesses/guide/page/what-volume-of-play-should-be-achieved-before-measuring-the-actual-rtp)

96% 是機率模型的期望值，不是每人投入 100 後保證拿回 96，也不是每 100 局固定回收 4%。例如兩個簡化模型都可以是 96%：48% 機率派彩 2×、其餘 0；或 1% 機率派彩 96×、其餘 0。兩者中獎率與波動差異極大。

對固定輪帶，本專案每軸獨立等機率抽停點。單一指定位置出現符號 s 的機率為 `該軸 s 數量 / 該軸長度`。但三格可見窗口互相依賴，20 條線也共用格子；不能把整局當成 15 格獨立抽樣或 20 次互相獨立的賭注。

在目前固定線、等機率停點、派彩可相加、無額外功能或封頂的前提下，各線的邊際期望相同，因此整體 RTP 可以由單線期望推得。**輪帶順序不改變這個期望，卻會改變同局多線命中的相關性、命中率、波動及最高獎。**所以調整符號數量後仍須排列實際輪帶、驗證整個盤面分布。

較複雜的產品會把基礎派彩、免費轉、連消、倍數及獎池的期望貢獻分開記帳，再加總為整體 RTP。若功能會重觸發，須把整段功能的期望算完，不能只算第一輪；若有額外下注的功能購買，還要單獨計算該模式分母與機率模型。[GLI-19 v3.0，4.7–4.8](https://gaminglabs.com/wp-content/uploads/2020/07/GLI-19-Interactive-Gaming-Systems-v3.0.pdf)

公開的現代產品可以看出「同樣約 96%」並不代表同樣玩法：NetEnt 官方目前列 Starburst 為 RTP 96.08%、命中率 23%、最高 800×；2025 年推出的 Reel Rush XXXtreme 為 RTP 96.06%、命中率 25%、最高 8,130×，還包含功能與免費轉。這兩個例子不是全產業平均，公開頁面也不足以逆推出完整輪帶或特定倍率尾端機率，不能把命中率直接拿來當本遊戲目標。[Starburst](https://netent.com/games/starburst)、[Reel Rush XXXtreme](https://netent.com/games/reel-rush-xxxtreme)

RNG 的工作是依既定分布產生結果；設計者事先透過輪帶、權重、賠率及功能規則決定分布。英國 RTS 7 禁止補償式自適應與因已出現的輸贏而干預機率；功能狀態依公開規則改變則另當別論。這裡引用其隨機性設計原則，不是在判定本虛擬籌碼專案的法律適用性。[RTS 7](https://www.gamblingcommission.gov.uk/manual/remote-gambling-and-software-technical-standards/rts-7-generation-of-random-outcomes)

## 使用者提供文章的可用與不可用之處

GammaStack 對權重、賠率、PAR 表及模擬的整體方向可作入門，但存在明顯錯誤：95% × 50 應為 47.5，而非文中的 45；低預算應選低 RTP 才能玩更久的說法沒有這種數學保證。它的 6³=216 示例適用於簡化的三軸單線等機率模型，不能直接代表三行多線盤面的全部結果。因此不採用文中的通用命中率範圍或玩法建議作為調參依據。[原文](https://www.gammastack.com/blog/the-basic-mathematics-of-slot-game-machines/)

## 現行模型的精確結果

重新執行 `npm run verify:math`：枚舉全部 4,000,000 組停點，並用獨立前綴計分器對照 9⁵ 種單線組合，再以固定 seed 模擬 1,000,000 局交叉檢查。精確 RTP 仍為 24/25=96%。以下不是只看幾十局的估計。

| 指標 | 現行值 |
|---|---:|
| 有派彩 | 50.0750% |
| 有派彩但仍虧損（0<W<B） | 30.4726% |
| 打平（W=B） | 2.6693% |
| 淨獲利（W>B） | 16.9331% |
| ≥20×，現行 BIG WIN | 0.59805%，平均 167.21 局一次 |
| ≥30× | 0.1628%，平均 614.25 局一次 |
| ≥50× | 0.10835%，平均 922.93 局一次 |
| ≥100× | 0.0002%，平均 500,000 局一次 |
| 真正最高派彩 | 120.65×，平均 2,000,000 局一次 |
| 單局回報標準差，以總下注為單位 | 3.187826× |

20×、30×、50× 門檻的變化不平滑，表示尾端有離散派彩的聚集。不能假設把門檻增加一半，出現次數就剛好少一半。

| 單局派彩 / 總下注 | 機率 | 對整體 RTP 的貢獻（百分點） |
|---|---:|---:|
| 0 | 49.9250% | 0 |
| 大於 0、小於 1 | 30.4726% | 11.9871 |
| 等於 1 | 2.6693% | 2.6693 |
| 大於 1、小於 5 | 11.6674% | 24.3308 |
| 5 至不足 20 | 4.6677% | 38.2580 |
| 20 至不足 50 | 0.4897% | 12.8782 |
| 50 至不足 100 | 0.10815% | 5.8550 |
| ≥100 | 0.0002% | 0.0216 |

≥20× 結果總共貢獻約 18.7548 個百分點，約占所有派彩期望的 19.54%。降低這一段時，若要保持 96%，必須把減少的期望補到其他結果；單純取消這些獎項會降低 RTP。

## 低分圖標與 WILD 的實際角色

下表是單一格位的機率；均勻停點下，上中下各格的邊際比例都相同，不是整軸三格「至少出現一個」的機率。

| 輪軸 | 低分 A/K/Q/J | 高分 H1–H4 | WILD |
|---|---:|---:|---:|
| R1 | 50% | 40% | 10% |
| R2 | 50% | 45% | 5% |
| R3 | 40% | 50% | 10% |
| R4 | 40% | 55% | 5% |
| R5 | 24% | 64% | 12% |
| 五軸等權平均 | 40.8% | 50.8% | 8.4% |

本模型高分符號主要靠前兩軸較少的某些符號阻擋連線，後軸則相對密集；其中 H1 在 R3 為 30%、R4 為 25%。它能達成 96%，但不符合「低分圖標常見、高分圖標稀少」的整體視覺預期。

依各條中獎線最終計分的符號分類：

| 計分符號類別 | RTP 貢獻（百分點） | 占派彩期望比例 |
|---|---:|---:|
| H1–H4 | 76.9848 | 80.19% |
| A/K/Q/J | 17.1703 | 17.89% |
| 純 WILD 計分 | 1.8450 | 1.92% |

**有 WILD 參與中獎前綴的線，合計貢獻 84.7459 個 RTP 百分點，約占全部回報的 88.28%。**這是另一種交叉分類，包含高低符號的 WILD 補線及純 WILD，不能加到上表。它不代表直接移除 WILD 就能推算新 RTP，也不代表 88.28% 的回合有 WILD。

因此目前的回報不只偏向高分圖標，也高度依賴 WILD 補線。調低高分符號頻率時，WILD 的數量、前三軸位置及純 WILD 3/4/5 連線獎都要一起檢查。

## 已計算的敏感度實驗

保持原賠率表，以符號數量建立假設新輪帶。各軸均等機率抽停點、每條線邊際分布相同，因此可精確計算期望；尚未排列實際輪帶，不聲稱已知其整局命中率、尾端機率或最大派彩。

| 假設改法 | RTP |
|---|---:|
| 原模型 | 96.0000% |
| 每軸低分圖標數量 ×1.5，其餘數量相對不變 | 58.5225% |
| 每軸低分圖標數量 ×2，其餘數量不變 | 44.8307% |
| 每軸 50 格，低分各 9 格、高分各 3 格、WILD 2 格 | 36.1708% |

第一個方案用所有原數量乘 2、低分改乘 3，以整數表示 1.5 倍。新增低分格會稀釋高分及 WILD 的比例。本專案原本主要靠後兩者返還籌碼，因此派彩期望急降；這不是提高低分圖標必然降低 RTP 的一般定律，而是本模型的量化結果。

## 建議的新版本設計規格

以下是待搜尋與驗證的產品目標，不是已完成或產業通用標準：

1. 保留 5×3、20 線及目前下注級距，長期 RTP 目標維持 96%。
2. 以各軸約 60–70% 低分圖標為起點，例如低分 65%、高分 31%、WILD 4%；每軸與各符號可不同，避免單一後軸堆積高分。這只是起始配比，不是最後輪帶。
3. 同步調整 3/4/5 連線賠率，優先增加低分圖標的常見回報。低分計分線占派彩期望先以 40–60% 作為比較目標，並追蹤 WILD 補線占比。
4. 把 ≥20× 真實派彩頻率先以約 1/600–1/1,000 作為候選比較範圍；相對目前約 1/167 明顯稀少。減少的回報移向小中獎，不能讓整體 RTP 跟著下跌。此目標是否與其他限制同時可行，須實際算出候選模型再確認。
5. 拆開動畫層級：20× BIG WIN、50× SUPER WIN、100× MEGA WIN 可作視覺分級草案。不要把 22×、32× 全部稱作超級大獎；動畫門檻修改本身不改 RTP，也不改真實派彩。
6. 比較候選時同時報告有派彩率、虧損派彩率、淨獲利率、20/50/100× 尾端、標準差，以及固定 30/100/300 局的期末餘額分布；本金與下注比須固定。降低尾端回報不保證一定有更高淨獲利率，需量化。

## 實作與驗收方式

先建立多組候選的 PAR／數學表，再挑符合體驗的模型。流程為：

`體驗目標 → 符號數量與賠率 → 單線精確期望 → 實際輪帶排列 → 全盤分布／可行的精確算法 → 固定 seed 模擬與短局測試 → 版本化發佈`

若輪帶變成每軸 100 格，直接全枚舉會有 100 億組，不能照搬目前 400 萬組的成本假設。RTP 可用符號組合加權精算；尾端與多線分布另選完整枚舉、動態規劃或可驗證的模擬。模擬必須附樣本數與誤差，極罕見最高獎不能只靠少量模擬宣稱已驗證。

賠率以單線下注倍數定義，目前總下注 500 代表每線 25；高分圖標 500 倍單線下注只等於 25 倍總下注。新的賠率若導致零碎籌碼，需先設計整數結算方案，再精算捨入後 RTP。

版本更新還需保留舊回合的規則版本與驗證能力。現有 `readState()` 對非當前版本、非舊 v2 的紀錄會重設本機狀態，未來升版須處理這個相容性問題；不能只改 `MODEL_VERSION`。伺服器歷史回合應繼續保留原派彩與原版本，不能套新規則重算舊帳。

本次只新增研究工具與報告，沒有調整遊戲機率、賠率或動畫門檻。
