## 排列原則

每軸固定 80 格，不是把短輪帶重複貼滿；每軸高分分散到四段，各 20 格中的高分數量接近該軸平均。相鄰重複為 6～8 次／80 格，接近參考表約 6%～11% 的重複頻率；沒有四格同圖標長堆疊。第一、二軸的 H1 夾心中間採不同低分圖標；後三軸保留短的 H1／WILD 混合窗口，以保留真實可達的 200 倍。

輪帶每軸有 58／68／68／70／74 種不同三格窗口；v4 為 31／36／29／32／33 種。這反映可見相鄰圖案變化增加，不代表 RTP 增加。

## RTP 與完整盤面驗證

| 指標 | 精確結果 |
|---|---:|
| 理論 RTP | 24/25 = 96% |
| 有派彩率 | 63.717578% |
| 淨獲利率 | 26.027218% |
| 單局標準差／總下注 | 1.627231 |
| 自然最高派彩 | 200 倍總下注 |
| 最高獎停點之一（0 起算） | 18 / 36 / 68 / 1 / 64 |

| 演出 | 派彩／總下注 | 精確停點組數 | 長期平均間隔 |
|---|---|---:|---:|
| BIG WIN | 20～不足 50 倍 | 906,512 / 3,276,800,000 | 3,614.73 回 |
| SUPER WIN | 50～不足 200 倍 | 151,896 / 3,276,800,000 | 21,572.65 回 |
| MEGA WIN | 恰好 200 倍 | 18 / 3,276,800,000 | 182,044,444.44 回 |

≥20 倍合計平均 3,095.92 回一次；上表三級互斥，平均間隔不是固定出獎週期。200 倍仍非常罕見，輪帶較短或高分圖標較多不代表會經常得到最高獎。

獨立算分器核對全部 59,049 種單線組合。相同三格窗口保留整數權重，再把前三軸會產生相同派彩算式的窗口組合合併，枚舉第四、五軸全部窗口。10459 組派彩算式 × 5180 組末兩軸窗口，精確涵蓋全部 3,276,800,000 組停點。總下注 65,536,000,000、總派彩 62,914,560,000，比值精確為 96%。這不是以模擬接近 96% 代替證明。

另以固定 seed 跑 100 萬局交叉核對，模擬 RTP 96.314160%；不拿這個短期數字當理論 RTP。

## 相容性與重現

v1～v4 規則保留在 src/models/，舊回合依原版本驗證。即使 v4 停點超過 79，餘額、原始派彩、歷史紀錄與相同請求的重送仍保留；新局使用 v5。向下轉動動畫沿用統一速度。

三種免費預覽停點（0 起算）：`{"big":[0,12,13,2,54],"super":[5,36,11,1,0],"mega":[18,36,68,1,64]}`。不扣籌碼、不寫紀錄。

1. `node scripts/analyze-reference-reels.js <使用者原始 JSON 檔>`：來源統計與映射基準。
2. `node scripts/design-v5-counts.js 2000000`：固定 seed 搜尋精確 96% 整數數量；只產生離線候選。
3. `node scripts/design-v5-reels.js`：固定 seed 排列 80 格輪帶。
4. `node scripts/verify-v5.js`：獨立算分、完整加權盤面、最高獎與三級可達性。
5. `node scripts/promote-model-v5.js`：檢查指紋、原賠率、96%、200 倍後套用。
6. `npm test`、`npm run verify:math`、`npm run build`。
7. `node scripts/sync-model-docs.js`：重建本文件與交付 JSON。

交付的 [reels.json](../output/reel-design-v5/reels.json) 為與使用者貼上內容相同的「五軸字串陣列」結構；[model.json](../output/reel-design-v5/model.json) 另含賠率、20 線座標、數量、預覽停點與精確結果。
