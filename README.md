# CROWNS OF KEMET 凱美特之冠 — 5×3／20 線

以使用者提供的素材製作。已接入固定 reel strip、20 線算分與精確 96% 理論 RTP；目前為本機內部試玩，尚未接入 Discord、OAuth 或正式後端。

## 啟動與檢查

Node.js 22.12+。執行 `npm install`、`npm run dev`，開啟 http://127.0.0.1:4187/ 。服務僅綁定本機。

- `npm test`：算分、Wild、亂數邊界、動畫輪帶一致性、帳本與舊紀錄遷移、精確 RTP。
- `npm run verify:math`：獨立算分器交叉核對 59,049 種單線符號組合，完整枚舉 400 萬種盤面，再跑 100 萬局模擬，產生 [數學報告](docs/math-report.json)。
- `npm run build`：建立靜態版本至 dist/。

### 計分規則

- 每條線在每軸取一格，從第一軸向右連續判定；至少 3 連才派彩，1、2 連為 0。從第二軸才開始的連線不派彩。
- 同一條線只取最高獎金，不累加三連、四連、五連。不同線各自計算後相加，即使共用同一格也可分別得獎。
- W 可替代 H1～H4、L1～L4，也可依 W 自身賠率形成連線。逐一計算所有合法解讀，僅支付該線最高的一項；W 不同時領取獨立獎與替代獎。
- 例如 `W W W H1 H1`：三連 W 為 50×，替代成五連 H1 為 500×，只支付 500×。`W W W L4 L4`：三連 W 為 50×、五連 L4 為 20×，只支付 50×。`H1 W H1 H2 H1` 則只支付三連 H1 的 20×。
- 第一版不含 Scatter、免費旋轉、倍數 Wild 或獎池；未來加入時須重新計算整體 RTP。里程碑僅作視覺演出，不額外發放籌碼。
- 總派彩 = 20 條線各自的最高派彩之和；淨損益 = 總派彩 − 總下注；結算餘額 = 下注前餘額 − 總下注 + 總派彩。
- 總下注為 20／100／200／500，單線下注為 1／5／10／25。派彩以整數記帳，不逐線取整。MAX BET 只選擇 500，不自動旋轉。

計算示例：總下注 100、單線下注 5；一條線 H1 三連得 5 × 20 = 100，另一條線 L1 四連得 5 × 15 = 75。本局總派彩 175，淨收益 +75。

## RTP 與完整盤面驗證

| 指標 | 精確枚舉結果 |
| --- | ---: |
| 理論 RTP | **96% = 24/25，精確值** |
| 有派彩局率（派彩 > 0，含小於下注） | 50.075% |
| 淨獲利局率（派彩 > 總下注） | 16.933125% |
| 單局回報標準差／總下注 | 約 3.187826 倍 |
| 最高可達派彩／總下注 | **120.65 倍** |
| 可達最高獎停點（從 0 起） | [15, 0, 8, 18, 15] |

完整枚舉以每線下注 1、總下注 20 計算：4,000,000 局總下注 **80,000,000**，總派彩 **76,800,000**，相除恰為 **0.96**。最高獎為 2,413／20 = 120.65 倍；總下注 100 時派彩 12,065。這是實際可達最大值，不是賠率表的理想算術上限。

第二項精確檢查：枚舉 9⁵ 種單線符號組合，以各軸符號數量乘積作權重，單線派彩加權總和為 **3,840,000**，除以 **4,000,000** 即 **0.96**。每條線在等機率循環停點下具有相同的邊際分布；20 線派彩可相加，期望值也可相加，無須假設各條線彼此獨立。本版沒有額外獎項、派彩封頂或逐線捨入。

另以固定 seed 960020 跑 1,000,000 局，模擬 RTP 為 **96.12247%**，常態近似 95% 區間 **95.49558%～96.74936%**。模擬僅作交叉檢查，精確 96% 的依據是上述枚舉；不要求有限局數剛好回收 96%。模擬使用可重現的 xorshift32；實際遊戲使用 Web Crypto 的 uint32 與 rejection sampling，避免直接取餘數造成偏差。

模型指紋（輪帶、賠率、線型一起計算 SHA-256）：

`209f894f373449220dfa179914ee9f746d6f497609d5c1ec9186445bcf7260fc`

變更賠率、符號數量、線數或加入免費旋轉／Scatter 時，必須重算 RTP 並增加規則版本。即使只更動 strip 順序，也須重算命中率、波動、最高獎並更新指紋。不得依玩家輸贏、餘額或短期 RTP 更改停點。

## 動畫、預覽與保存

- 每局先獨立抽取五個停點，再產生真實 5×3 盤面及各線派彩。帳本先存後播，動畫保持向下轉速，從左到右每隔 230 ms 急停，接上約 190 ms 的輕微下衝與向上回彈。上下保留輪帶相鄰格，回彈不露空白、不改變停點。
- 得獎線每 1.6 秒依線號順序逐條循環：顯示完整線型、突出實際得獎段、壓暗其他格子；各線得分與倍率可在「遊玩紀錄」查看。開始新局或重設會取消舊線條演出；大獎／里程碑畫面期間暫停逐線展示，關閉後繼續。
- 主畫面固定於視窗內，遊戲依可用高度縮放，不捲動頁面。遊戲下方顯示最近一局的中獎總得分（派彩，不扣下注），派彩大於 0 就顯示，即使低於下注也顯示；未中獎留白且保留版面空間。中獎數字從 0 遞增，約 1.2 秒到達總得分；按下下一次 SPIN 立即清空並取消舊數字動畫。重新開啟時直接顯示最近紀錄；大獎預覽也展示跳分，但不影響籌碼或紀錄；減少動態效果時直接顯示最終分數。右上角「遊玩紀錄」「遊玩介紹」以彈出視窗顯示，長內容僅在視窗內捲動；「重設試玩」位於遊玩介紹內。
- 派彩高於下注才播放獲利慶祝；派彩至少總下注 20 倍播放 BIG WIN。12,000 里程碑只有演出，不額外送籌碼。
- 「大獎預覽」使用真實可達的五個 W 中央停點，依相同賠率計算，但不扣款、不新增紀錄，也不納入 RTP。音效需手動開啟；減少動態效果時縮短演出；切到背景會結束演出並暫停繪製。
- 最近 100 局保存時間、局號、規則版本、總下注、單線下注、五停點、完整盤面、各得獎線明細、派彩、淨損益與前後餘額。相同局號在保留的紀錄內不重複結算。
- 沿用 `kemet-slot-preview-v2` localStorage key，資料結構升為 version 3。既有餘額與舊展示紀錄保留，標記舊規則（舊模型 RTP 235%，不能與本版統計混用）。舊盤面沒有合法停點，啟動時顯示新輪帶初始盤面；新紀錄可由停點還原。
- 重設試玩恢復 10,000 測試籌碼並清除該瀏覽器紀錄。清除瀏覽器資料也會失去紀錄。本機帳本可被修改，不具正式防作弊或跨裝置能力；Discord 公開版應由伺服器抽停點、驗證下注與結算。

## 素材

- `images/main.png`／`main.json`：機台、標誌、阿努比斯、BIG WIN 裝飾；`images/background.png`：使用者提供的背景。
- `images/symbols.png`／`symbols.json`：H1～H4、L1～L4、W 九符號，依上表映射；保留語意 ID 以相容舊紀錄。
- H、W 與機台背景由使用者提供。L 為先前生成並由使用者整合的 A／K／Q／J。缺素材先詢問位置，不自行產圖。
- 直接載入 PNG 並解析圖集像素座標，保留透明邊界。JSON 的 `meta.image` 仍是 `symbol.png`；目前實際載入 `symbols.png`，若日後改成 JSON 自動載入需統一檔名。
- 阿努比斯已改用 `images/spine/anubis/` 的原始 Spine 3.8.99 JSON／atlas／PNG，取代靜態圖。平常循環 `idle`（2 秒），每局只要 `wins.length > 0` 就播放一次 `action`（約 1.667 秒），完整播完後混合回 `idle`；派彩低於下注也觸發，多條贏線不重複排入動作。大獎預覽同樣觸發，按下 SPIN 或未中獎結算不會重設動畫進度；重設遊戲才會取消舊動作並重新播放 `idle`。
- 主遊戲維持 PixiJS 8；Spine 3.8 由 `@pixi-spine/runtime-3.8`／Pixi 7 相容層在透明離屏畫布繪製，再作為 Pixi 8 紋理呈現。保留角色網格、deform、旋轉 atlas 與 additive 光效，原始素材不改版號。角色更新上限約 30 fps，跟隨遊戲 ticker 暫停；相容層按需載入。載入時複製骨架資料，移除直式符號專用的 m 裁切遮罩、背景、邊框及大片 shadow／overall_shadow，保留身體各部位陰影與火焰。原始 JSON／atlas／PNG 不變；透明離屏畫布擴為 800×1280，容納完整雙腳與 action 光效。窄畫面縮放放在左側機框，沒有佔滿整軸的角色符號。
- 相容層依據：[Pixi Spine 3.8 runtime](https://github.com/pixijs-userland/spine)；[官方版本相容說明](https://esotericsoftware.com/spine-pixi)。目前 legacy adapter 在 Pixi 7.4 會產生一次 `rgb2hex` 棄用提示，不影響動畫；不修改第三方套件來隱藏訊息。
