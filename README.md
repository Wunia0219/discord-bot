# CROWNS OF KEMET 凱美特之冠 — 5×3／20 線

以使用者提供的素材製作。已接入固定 reel strip、20 線算分與精確 96% 理論 RTP；已完成 Discord Activity SDK 握手，使用者已成功在 Discord 內試玩。本機測試版已啟用 OAuth 基本身分登入與 Node 後端，使用者已確認實際 Discord 登入成功；已實作伺服器錢包、每日簽到、管理員指令與後端結算，進入測試伺服器驗收；尚未部署朋友正式環境。

## 啟動與檢查

Node.js 24（伺服器錢包使用內建 SQLite）。執行 `npm install`、`npm run dev`，開啟 http://127.0.0.1:4187/ 。服務僅綁定本機。

- `npm test`：算分、Wild、亂數邊界、動畫輪帶一致性、帳本與舊紀錄遷移、精確 RTP。
- `npm run verify:math`：獨立算分器交叉核對 59,049 種單線符號組合，完整枚舉 400 萬種盤面，再跑 100 萬局模擬，產生 [數學報告](docs/math-report.json)。
- `npm run build`：建立靜態版本至 dist/。
- `npm run activity:serve`：建置並在 4188 提供 Discord 測試用靜態遊戲。設定方式見 [Discord Activity 私人測試接入](docs/discord-activity-setup.md)。

指令、權限、測試步驟、Docker 與持久磁碟部署及備份方式見 [錢包與正式交付](docs/wallet-and-release.md)。目前只在自己的測試伺服器驗收，未發布到朋友伺服器。

## 自適應版面與操作

- BIG WIN 採全畫面壓暗、青綠羽翼光環、原圖集蓮花與標題，以及金色跳分。BIG WIN／COINS／控制框上方得分共用 `images/fonts/kemet-gold.fnt` 與 WebP；素材、sprite sheet 規格和重建方式見 [BIG WIN 演出與金色數字](docs/big-win-assets.md)。
- 啟動時顯示深靛藍背景、原圖集的短版 Logo 與金綠色動畫讀條，不顯示額外文字或百分比。進度依 Discord 握手、引擎、圖集、背景與 Spine 完成階段推進，並非下載位元組百分比；全部就緒後淡出，才開放操作。失敗時停止讀條並提供重新載入圖示；載入狀態仍提供給螢幕閱讀器。支援系統減少動態效果設定。
- 電腦版固定「機台在上、單排操作列在下」構圖，以 1160×824 設計尺寸依可用寬高整組等比例縮放；Discord 視窗縮小或全螢幕不會切換為側欄。優先依 Discord 的 platform 區分裝置，一般瀏覽器以觸控／滑鼠能力判斷。只有手機使用直向多排、低高度橫向右側操作列；手機直向（可用寬度小於 500px）讓 COINS 獨占一列，完整顯示 100,000／1,000,000。桌面 COINS 欄位的設計寬度至少 176px，隨整組構圖縮放。
- 機台保持原始比例，縮減透明留白並放大阿努比斯；背景填滿視窗，主頁不產生捲動。說明與紀錄視窗可獨立捲動。
- 支援動態視窗高度與 Discord／手機安全邊界；Activity READY 後請求解除方向鎖定。Discord 外層容器的黑邊仍由客戶端決定。
- 空白鍵可啟動 SPIN，點過下注或工具列按鈕後仍有效；長按不連續觸發，轉動中、尚未載入或開啟視窗時不下注。輸入欄位保留原本鍵盤行為；其他按鈕可用 Tab 選取、Enter 啟動，鍵盤焦點使用金色提示，滑鼠點擊不留下外框。
- 每次開啟遊戲時，得分區保持空白；本次遊玩中得獎才顯示跳分。餘額與歷史紀錄照常保留。
- 頂部只保留靠右的遊戲工具列，移除左上品牌標誌。人物視野包含 idle／action 的肩甲、手部與腳部範圍，避免放大後再被畫布左緣切掉。
- 本次以瀏覽器模擬 7 種電腦視窗（800×450 至 2560×1440，含 1224×588 Discord 視窗）及 5 種手機／平板直橫向尺寸；確認電腦機台與操作列比例一致，主頁無溢出、按鈕無重疊。Discord 新版版面與手機端仍須實機確認。

## 20 線賠率表（已套用 kemet-20-v2）

新版維持精確 96% RTP，各軸低分圖標占 64～65%，20 倍以上派彩平均約 958 局一次。詳細設計與舊版比較見 [新版數學與演出](docs/model-v2.md)。舊版資料保存在 src/models/v1 與 docs/math-report-v1.json。

所有倍率乘以單線下注，單線下注 = 總下注 ÷ 20；不另外返還本金。

## RTP 與完整盤面驗證

| 指標 | 精確結果 |
|---|---:|
| RTP | 24/25 = 96% |
| 有派彩局率 | 49.5250% |
| 淨獲利局率 | 27.1570% |
| 單局標準差／總下注 | 1.926832 |
| 最高可達派彩／總下注 | 144.1 倍 |
| 最高獎停點 | 13 / 10 / 6 / 6 / 13 |
| ≥20 倍 | 4,177 / 4,000,000；平均 957.63 局一次 |
| ≥50 倍 | 43 / 4,000,000；平均 93,023.26 局一次 |
| ≥100 倍 | 20 / 4,000,000；平均 200,000 局一次 |

完整枚舉以總下注 20 計算，總下注 80,000,000，總派彩 76,800,000。單線符號加權驗證為 3,840,000 / 4,000,000 = 96%；不同線的期望可相加，不需假設互相獨立。最高獎 2,882／20 = 144.1 倍，總下注 500 時為 72,050。

另以 seed 960020 模擬 1,000,000 局，RTP 96.028775%，常態近似 95% 區間 95.651793%～96.405757%。模擬僅交叉檢查；正式抽樣採伺服器 crypto.randomInt，本機試玩採 Web Crypto rejection sampling。平均間隔不是保證週期，短期派彩不需等於 96%。

模型 SHA-256：`6910fad290e8933addd0f127bd92403a39eea0d5d354c512b89789ae129820c9`。變更輪帶、順序、賠率、線型或功能都須重新驗證並升版。不可依餘額、玩家輸贏或短期 RTP 調整機率。

## 動畫、預覽與保存

- 每局先獨立抽取五個停點，再產生真實 5×3 盤面及各線派彩。帳本先存後播，動畫保持向下轉速，從左到右每隔 230 ms 急停，接上約 190 ms 的輕微下衝與向上回彈。上下保留輪帶相鄰格，回彈不露空白、不改變停點。
- 得獎線每 1.6 秒依線號順序逐條循環：顯示完整線型、以埃及金飾外框突出實際得獎段、壓暗其他格子；每次展示得獎線都播放一次 960ms 雙凸縮（1 → 1.16 → 1 → 1.11 → 1），包含同一條線輪播回來時。素材與動畫規格見 [得獎圖標與外框](docs/winning-symbol-effects.md)；各線得分與倍率可在「遊玩紀錄」查看。開始新局或重設會取消舊線條演出；大獎／里程碑畫面期間暫停逐線展示，關閉後繼續。
- 主畫面固定於視窗內，遊戲依可用高度縮放，不捲動頁面。控制框正上方顯示最近一局的中獎總得分（派彩，不扣下注），派彩大於 0 就顯示，即使低於下注也顯示；未中獎留白。中獎數字從 0 遞增，約 1.2 秒到達總得分；按下下一次 SPIN 立即清空並取消舊數字動畫。重新開啟時得分留白；大獎預覽也展示跳分，但不影響籌碼或紀錄；減少動態效果時直接顯示最終分數。右上角「遊玩紀錄」「遊玩介紹」以彈出視窗顯示，長內容僅在視窗內捲動；「重設試玩」位於遊玩介紹內。
- 派彩高於下注才播放獲利慶祝；派彩 20～不足 50 倍播放 BIG WIN，50～不足 100 倍播放 SUPER WIN，100 倍以上播放 MEGA WIN。12,000 里程碑只有演出，不額外送籌碼。
- 「大獎預覽」可選 BIG／SUPER／MEGA，分別使用真實可達的停點，依相同賠率計算，但不扣款、不新增紀錄，也不納入 RTP。音效需手動開啟；減少動態效果時縮短演出；切到背景會結束演出並暫停繪製。
- 最近 100 局保存時間、局號、規則版本、總下注、單線下注、五停點、完整盤面、各得獎線明細、派彩、淨損益與前後餘額。相同局號在保留的紀錄內不重複結算。
- 沿用 `kemet-slot-preview-v2` localStorage key，資料結構升為 version 3。既有餘額與舊展示紀錄保留，標記舊規則（舊模型 RTP 235%，不能與本版統計混用）。舊盤面沒有合法停點，啟動時顯示新輪帶初始盤面；新紀錄可由停點還原。
- 重設試玩恢復 10,000 測試籌碼並清除該瀏覽器紀錄。清除瀏覽器資料也會失去紀錄。本機帳本可被修改，不具正式防作弊或跨裝置能力；Discord 公開版應由伺服器抽停點、驗證下注與結算。

## 素材

- `images/main.png`／`main.json`：機台、標誌、阿努比斯、BIG WIN 裝飾；`images/background.png`：使用者提供的背景。
- `images/symbols.png`／`symbols.json`：H1～H4、L1～L4、W 九符號，依上表映射；保留語意 ID 以相容舊紀錄。
- H、W 與機台背景由使用者提供。L 為先前生成並由使用者整合的 A／K／Q／J。缺素材先詢問位置，不自行產圖。
- 直接載入 PNG 並解析圖集像素座標，保留透明邊界。JSON 的 `meta.image` 仍是 `symbol.png`；目前實際載入 `symbols.png`，若日後改成 JSON 自動載入需統一檔名。
- 阿努比斯已改用 `images/spine/anubis/` 的原始 Spine 3.8.99 JSON／atlas／PNG，取代靜態圖。平常循環 `idle`（2 秒），每局只要 `wins.length > 0` 就播放一次 `action`（約 1.667 秒），完整播完後混合回 `idle`；派彩低於下注也觸發，多條贏線不重複排入動作。大獎預覽同樣觸發，按下 SPIN 或未中獎結算不會重設動畫進度；重設遊戲才會取消舊動作並重新播放 `idle`。
- 主遊戲維持 PixiJS 8；Spine 3.8 由 `@pixi-spine/runtime-3.8`／Pixi 7 相容層在透明離屏畫布繪製，再作為 Pixi 8 紋理呈現。保留角色網格、deform、旋轉 atlas 與 additive 光效，原始素材不改版號。角色更新上限約 30 fps，跟隨遊戲 ticker 暫停；相容層按需載入。載入時複製骨架資料，移除直式符號專用的 m 裁切遮罩、背景、邊框及大片 shadow／overall_shadow，保留身體各部位陰影與火焰。原始 JSON／atlas／PNG 不變；透明離屏畫布擴為 800×1280，容納完整雙腳與 action 光效。窄畫面縮放放在左側機框，沒有佔滿整軸的角色符號。
- 相容層依據：[Pixi Spine 3.8 runtime](https://github.com/pixijs-userland/spine)；[官方版本相容說明](https://esotericsoftware.com/spine-pixi)。目前 legacy adapter 在 Pixi 7.4 會產生一次 `rgb2hex` 棄用提示，不影響動畫；不修改第三方套件來隱藏訊息。
